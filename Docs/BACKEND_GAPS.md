# Backend Gaps — Endpoints needed by the frontend

These endpoints do not exist yet. The frontend works around them (mock data / localStorage) for now. Implement them before removing the mocks.

## Priority order

### 1. Product browsing
```
GET /api/v1/products
  ?category=clothing
  &q=linen+shirt
  &min_price=500
  &max_price=5000
  &sort=price_asc|price_desc|rating|newest
  &limit=20
  &offset=0
```
**Why:** Home page, category pages, and "Load more" use `POST /search` as a workaround (searching with category name as `text_prompt`). A real list/browse endpoint avoids the embedding round-trip and supports true pagination.

### 2. Category list
```
GET /api/v1/categories
```
Returns: `[{ slug, label, product_count }]`. Currently hard-coded in the frontend.

### 3. Server-side price insight
```
GET /api/v1/products/{id}/price-insight
```
Returns: same shape as the client-side `lib/priceInsight.ts` output: `{ verdict, min, max, average, current, percentile, evidence }`. The frontend computes this from `price_history` for now; replace with this endpoint when available.

### 4. Authentication (JWT, httpOnly cookie)
```
POST /auth/signup          { name, email, password }  → 201 { user }
POST /auth/login           { email, password }         → 200 { user }
GET  /auth/me                                          → 200 { user }
POST /auth/logout                                      → 204
POST /auth/change-password { old_password, new_password }
POST /auth/delete-account
```
Cookie: `access_token` (httpOnly, Secure, SameSite=Lax). Frontend currently uses a localStorage SHA-256 hash mock — **not secure for production**.

### 5. User data
```
GET  /me/cart                 → [CartItem]
POST /me/cart                 { product_id, quantity }
DELETE /me/cart/{product_id}

GET  /me/saved                → [SavedItem]
POST /me/saved                { product_id }
DELETE /me/saved/{product_id}

GET  /me/history              → [HistoryEntry]   (store clicks + self-reported purchases)
POST /me/history              { product_id, store, ts }

GET  /me/activity             → [ActivityEvent]
POST /me/activity             { type, product_id?, category?, brand?, query?, price?, ts }
DELETE /me/activity           (clear all)

GET  /me/preferences          → { favorite_categories[], budget_min, budget_max, personalization_paused }
PUT  /me/preferences          { … }
```

### 6. Recommendations
```
GET /me/recommendations
  ?limit=8
```
Returns: `recommended_products[]` — same product shape as search results.

### 7. Store-click redirect tracking
```
POST /links/click
  { product_id, store_name, destination_url }
  → 200 { redirect_url }
```
Allows the backend to record the click before the user navigates to the store. The frontend validates the URL is `http`/`https` before using it.
